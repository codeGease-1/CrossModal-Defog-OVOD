## 第一阶段：测清 49% 的来源，再做等价优化

当前 256 输入动态模型 7.31 ms，RGB16 4.91 ms，同输入回归 6.45 ms。差值不能用不同测量批次的零件耗时直接相加解释。先冻结权重和输入，在同一次顺序测量里拆分输入检查、原始先验、引导滤波、标定插值、内容特征、骨干、系数头、门控和凸融合；同时记录同步和 Python 调度。完整 RGB→H 的主计时继续保留，不能只报骨干时间。

源码可见 FastCandidates.forward 的 bool(torch.isfinite(...).all() & ...) 将 GPU 归约结果用于 Python 判断；这是值得测量的同步位置，尚未证明它是主要瓶颈。可探索在受检入口验证一次、内部计算复用中间量、减少张量拼接与调度，保持外部输入校验和数值契约。执行图或编译类优化先检查当前环境兼容性，不预设收益。所有先验控制享有同样优化机会。

诊断/优化可先预算 5—10 V100 分钟，不训练。每个新实现比较 CPU/CUDA、常量/边界尺寸、512 个已暴露开发样本的先验和最终预测；先验绝对差不超过 1e-6、网络差不超过 1e-5，出现差异先查原因，不靠调容差掩盖。测试 PNG 到 CPU H、256/512、batch=1 的 p50/p95、PyTorch 峰值显存；重复至少三轮测量，保留原版。5—10 分钟为拟议上限，超出需重新核算，不代表已消耗预算。

## 第二阶段：分清 A 覆盖与生成机制失配

先按已有逐样本记录分别比较 A、亮度、雾型、强度和内容代理；本次 audit.json 已提供主要分层入口。分别报告每候选误差/偏差、共同错误和凸融合下界。保持校正与融合的诊断分离，oracle 不进入训练。

若训练分布要扩展，首先只检验 A 覆盖，仍在线性辐射域合成、返回显示 RGB，避免同时引入新的生成机制而无法归因。只使用训练原景，重新冻结 A 采样、亮度、t、配对数量、全部随机种子和统计量规则。标定按新训练分布对所有先验方法一致重拟合；新旧成绩不能当成严格对照。

一轮最多三个主要实验组：当前联合动态结构、RGB16、同输入直接回归。各三个种子，全部从公平起点提供相同训练配对和更新机会，不单独给校正模型增加训练数据；模型结构先不扩张。若重训 36 轮、batch=8、1536 对，九个任务约 55—80 V100 分钟，另留 5—10 分钟用于标定、完整评估和成本；这是依据既有每轮耗时的粗估，启动前应以小步实测修订。辅助损失与检查点规则差异继续披露，尚不能声称同构辅助头的因果公平已完全解决。

生成机制压力作为单独研究问题：首先保证训练/推理编码契约清晰，再判断是否需要混合机制训练。若混合，两类 RGB 控制必须获得相同混合配对；推理不能使用机制真值、t/A 或场景 ID。不能依靠单图自动判域承诺普适修复。
