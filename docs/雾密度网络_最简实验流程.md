# 雾密度网络：v1-nocolab 最简实验流程

更新于 2026-10-25。适用于恒源云等提供 Linux、终端与 NVIDIA GPU 的算力平台。以下是服务器 **Bash 终端命令**，全部从项目根目录执行；也可使用[配套 notebook](雾密度网络_最简实验流程.ipynb)。

## 1. 获取代码并设置路径

使用平台的 PyTorch GPU 镜像。先在平台控制台确认持久化磁盘的挂载目录，将下面的 `WORK_ROOT` 改为该磁盘上的实际工作目录。不同平台路径不同，不要原样使用占位路径。

```bash
export WORK_ROOT=/path/to/persistent/workspace  # 必改
mkdir -p "$WORK_ROOT"
cd "$WORK_ROOT"
git clone --branch v1-nocolab --single-branch https://github.com/codeGease-1/CrossModal-Defog-OVOD.git
cd CrossModal-Defog-OVOD
export PROJECT_ROOT="$PWD"
export DATASET_ROOT="$WORK_ROOT/datasets/RSHaze+"
export OUTPUT_ROOT="$WORK_ROOT/experiments"
export RUN_NAME=spatial_v3_run01
export RUN_DIR="$OUTPUT_ROOT/$RUN_NAME"
git branch --show-current
git rev-parse HEAD
```

先确保远端 `v1-nocolab` 已包含本次改动。若平台无法访问 GitHub，也可上传本分支的源码包，解压后进入项目目录，再设置上述路径变量；不要上传本机 `.venv`。已有仓库直接进入并确认版本，无需重复 clone。

## 2. 安装依赖、检查 GPU

使用平台镜像中已经安装 CUDA 版 PyTorch 的 Python：

```bash
which python
nvidia-smi
python -m pip install -r requirements.txt
python scripts/utils/setup_environment.py --require-cuda
python scripts/utils/static_check.py
python -m unittest scripts.test.test_review_regressions scripts.test.test_stage1_bugfixes -v
python scripts/utils/smoke_test.py
```

`--require-cuda` 会实际创建 CUDA 张量；失败时先修复环境再训练。训练脚本自动选用可见 GPU。手动安装时参考 [PyTorch 官方安装选择器](https://pytorch.org/get-started/locally/)。本地 CPU 检查可省略 `--require-cuda`，不代表完成 GPU 验证。

## 3. 上传并解压数据

通过平台文件上传、SFTP 或自己的数据盘准备 RSHaze+，使 `DATASET_ROOT` **直接包含三个子集**：

```text
RSHaze+/
├── RSHaze_G/{train,test}/{synhazypng,cleanpng}/*.png
├── RSHaze_L/{train,test}/{synhazypng,cleanpng}/*.png
└── RSHaze_S/{train,test}/{synhazypng,cleanpng}/*.png
```

例如已上传 ZIP，可以执行 `python -m zipfile -e /实际路径/RSHaze+.zip "$WORK_ROOT/datasets"`。解压后若多包一层目录，调整 `DATASET_ROOT` 指向实际数据根目录；无需复制整份数据。

## 4. 固定配置与划分

```bash
python scripts/utils/prepare_experiment.py \
  --dataset-root "$DATASET_ROOT" --output-root "$OUTPUT_ROOT" \
  --run-name "$RUN_NAME" --image-size 256 --batch-size 4 --num-workers 2
```

此命令核验数据目录，并在 `$RUN_DIR` 保存绝对路径配置 `train_config.yaml`、固定划分 `rshazeplus_split.json` 和代码/环境记录。再次运行会核对已有配置与划分；不同设置需换 `RUN_NAME`。有权重而丢失原 manifest 时会拒绝重新划分。

## 5. 短训练 → 继续至 50 轮

```bash
# 首次短训练
python -u scripts/train/train_haze_density.py --config "$RUN_DIR/train_config.yaml" --epochs 5

# 确认短训练正常后，从 latest.pth 继续，累计训练到第 50 轮
python -u scripts/train/train_haze_density.py --config "$RUN_DIR/train_config.yaml" \
  --epochs 50 --resume "$RUN_DIR/checkpoints/latest.pth"
```

`best.pth` 用于评估，`latest.pth` 用于续训；日志在 `$RUN_DIR/results/train_log.csv`。新训练不会覆盖已有权重。训练中断后，重新设置原路径变量，使用原配置和 `latest.pth` 续训，最多重新计算尚未保存的那一轮。

长训练可先在终端执行 `tmux new -s haze`，在会话内完成上述步骤；`Ctrl+B` 后按 `D` 退出显示，`tmux attach -t haze` 返回。`tmux` 只保持终端会话，无法阻止平台关机或回收实例。

## 6. 最终评估与独立 Benchmark（可选）

调参时使用验证集；[notebook 第 6 节](雾密度网络_最简实验流程.ipynb)可以查看验证集原图、伪标签、预测与误差。方案确定后才运行测试集：

```bash
python scripts/evaluate/evaluate_haze_density.py \
  --checkpoint "$RUN_DIR/checkpoints/best.pth" --dataset_root "$DATASET_ROOT" \
  --split_file "$RUN_DIR/rshazeplus_split.json" \
  --image_size 256 \
  --output_dir "$RUN_DIR/test_evaluations/$(date +%Y%m%d_%H%M%S)"

python scripts/benchmark/run_benchmark.py --data-root "$DATASET_ROOT" \
  --checkpoint "$RUN_DIR/checkpoints/best.pth" \
  --output "$RUN_DIR/benchmarks/$(date +%Y%m%d_%H%M%S)"
```

若第 4 节修改了图像尺寸，测试命令的 `--image_size` 也应改为相同值。没有权重也可运行 Benchmark，去掉 `--checkpoint`；学生正确性会标为 NOT EVALUATED。只有缺少指定官方小样本且允许联网时，才加 `--fetch-small-sample`（24 MiB 上限）。详细定义见 [Benchmark 说明](guides/haze_density_benchmark.md)。

## 7. 保存实验

备份整个 `$RUN_DIR` 和本次代码提交/源码包。请核对平台对关机、删除实例和数据盘的保存规则；训练直接写入所选持久化目录，不再有额外同步步骤。

显存不足时，新实验减小 `--batch-size`；DataLoader 多进程/共享内存报错时可用 `--num-workers 0`。迁移机器续训时优先恢复相同绝对路径；当前严格恢复检查会拒绝修改数据根目录或 manifest 路径，避免混用实验。

输出是先验定义的相对雾感评分。测试集 MAE/RMSE 衡量伪标签拟合；独立 Benchmark 当前只有一个地理组，不能证明跨地区泛化。本次迁移不构成真实 RSHaze+ 训练或云端 GPU 实测。
