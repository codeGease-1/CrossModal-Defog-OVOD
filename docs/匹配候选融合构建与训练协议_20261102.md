# 匹配候选融合：构建与训练协议

目标保持不变：在相同数据、监督与训练机会下，检验受限候选校正能否以相近或更少参数接近同骨干RGB回归，并公开完整推理成本。精度接近不等于完整成本目标已经达到。

本轮全部源码编辑、测试及训练在云端/mnt。独立工作树：/mnt/CrossModal-Defog-OVOD-matched-gate-20261102，分支codex/matched-gate-20261102，基线90070ae。原工作树和旧best/latest保持不变，没有提交或推送。

## 实现

- MatchedFusion：复用冻结校正器的RGB编码特征，两组门控看到完全相同的19通道特征；一组融合原候选，一组融合完全冻结的校正候选。
- 门控2803参数；完整神经网络221161参数。先验、固定标定和内容描述仍参与推理，其常量与耗时单列。
- 门控只输出三张softmax权重图。候选校正和融合分离，没有自由H残差或额外RGB强度头。
- 新增同骨干宽度16的纯RGB回归；保留同输入直接回归与RGB32对照。
- 所有推理只接受有雾RGB。亮度、纹理只是内容特征，无语义分割或新增物理项。

## 公平训练机会

新增主要模型只有原候选门控、校正候选门控、纯RGB16三种，每种42/43/44三个种子。另对已有direct_same16和RGB32继续训练，属于必要对照续训。

校正器既有18轮训练加上门控18轮；每个RGB对照均获得36轮、6912次批次更新机会。既有RGB对照从原latest的模型、Adam、scaler与随机状态继续训练。所有方法使用同1536训练配对、512开发配对、batch8、学习率.001、AMP和既有task loss。先验与标定始终FP32。比较以完整训练机会为准，不把校正器预训练当免费条件。

校正辅助目标与直接H回归的目标结构不同，这是结构差异，不声称相同优化过程。原候选门控仍使用校正训练得到的特征，是受控候选消融，不是历史v2。

## 已通过检查

CPU/CUDA三种尺寸下的三候选重建差均为零；仅门控收到梯度；候选和校正器参数保持冻结；融合输出位于候选范围；优化器状态恢复检查差为零。首个已训练门控在CPU上通过纯RGB、奇数尺寸65×65推理。64个原景像素哈希与旧清单一致，训练/开发原景组无交叉。数据与目标哈希、源码快照、环境和命令已登记。

## 自动运行与停止边界

实验输出：工作树下experiments/matched_fusion_20261102。training.log记录逐轮过程，每个latest包含可恢复的优化器/scaler/RNG。postprocess_status.json记录训练后的磁盘恢复测试、旧开发集三条件评价、完整成本测量与全种子导出。后处理等待训练进程退出，避免并发训练污染推理计时。

只使用既有开发原景；不打开新确认，不自动扩展模型搜索。已有确认全部按开发参考处理。报告逐候选误差、共同错误、包络与oracle下界、整体与空间指标、清晰响应、门控均值化/打乱、困难内容代理、逐种子与配对原景置信区间。全部推理参数、FP32先验/标定/内容、AMP网络、PNG解码与传输到CPU输出计时均纳入记录。

最终报告由scripts/matched_evaluation/finish.py生成到docs/匹配训练机会的候选校正动态融合报告_20261102.md。当前构建文档不是最终效果结论，开发筛查也不等于真实遥感雾验证。

训练恢复命令：在上述工作树运行 python -u scripts/matched_fusion/run.py --stage train。若后处理失败，先查看postprocess_status.json和对应日志，按其中记录的单阶段命令恢复，不覆盖旧证据。

若三个种子不支持稳定收益，保留失败并停止堆模块；即便开发精度达到5% MAE、.01相关、.005清晰响应容差，也须继续审阅完整成本和种子波动。程序化原景不能替代真实遥感数据资格检查。
